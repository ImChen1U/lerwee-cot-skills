# 测试流程

## 接口回归

1. GET /backend_api/lerwee/prompt-template/view?id=场景ID 取场景详情。
2. POST select-form 解析手工输入。
3. POST select-data 获取候选对象。
4. 按规则选择对象，POST build 执行表达式采集。
5. POST chat-stream 获取模型回答和 CoT。
6. 自动检查：SQL 不合法、表达式残留、数据缺失、危险命令、表格损坏、结论缺失、告警口径错误。

## 浏览器冒烟

1. 打开 http://192.168.1.79:8180 或 http://192.168.3.92 的场景管理页。
2. 按名称精确找到场景。
3. 点击进入交互页。
4. 选择对象，点击"开始对话"。
5. 等模型输出稳定，确认最后有"处理结论"。
6. 点击"查看 CoT"，检查原始数据和表达式错误。
7. 保存回答、CoT、截图和测试时间。

## 代表性回归

表达式、SQL、阈值、决策树或输出结构变化后执行。

- 有异常监控状态：2 正常 + 2 异常。
- 无异常监控状态：4 个数据路径不同的正常对象。
- 单选分 4 次；多选可一次选 4 个。
- 每次必须查看 CoT。

## 单次测试检查清单

- 对象名称和 IP 正确。
- 无残留 {#...} 表达式。
- 无 SQL 不合法或方言错配。
- 告警列只用近 7 天告警。
- Markdown 表格列数一致。
- 数据不足写"暂无法判断"。
- 处理结论明确是否处理、依据和下一步。
- P0/P1 动作有执行位置、确认条件和风险。
